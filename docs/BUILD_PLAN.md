# ПЛАН СБОРКИ В GODOT 4.3 — «МЁРТВЫЙ ЭФИР»

Проект уже лежит в этом репозитории в виде кода: все шаги ниже описывают,
как он устроен, как открыть его в редакторе и как воспроизвести/расширить
каждую часть вручную. Порядок шагов — порядок зависимостей.

## 0. Требования
- Godot 4.3 stable, Forward+ (Vulkan). Контент работает и на Mobile, но
  экспозиция/тонемап настроены под Forward+.
- Первый запуск: Godot сам импортирует `sounds/*.wav` (файлы `.import`
  создаст редактор — их нет в репозитории намеренно).

## 1. Проект и автозагрузка
1. `project.godot`: main_scene `res://scenes/main.tscn`; окно 1280×720,
   stretch `canvas_items`/`expand`; MSAA 3D = 2×; clear color #030405.
2. Автолоады строго в порядке: `Boot` (scripts/boot.gd) → `Game`
   (scripts/game.gd) → `Sound` (scripts/sound_bank.gd).
3. Управление НЕ хранится в project.godot: `boot.gd` регистрирует действия
   (`move_w/a/s/d`, `sprint`, `crouch`, `interact`, `flashlight`, `throw`,
   `pause`, `choice_1`, `choice_2`) в `_enter_tree()` через `InputMap.add_action`.
   Это исключает рассинхронизацию сериализации InputEventKey.

## 2. Данные карты
1. Карты не рисуются руками: `tools/build_maps.py` — источник правды.
   Правка станций происходит в нём, после чего `python3 tools/build_maps.py`
   перегенерирует `scripts/station_data.gd`.
2. Валидатор внутри build_maps.py проверяет: границы, длины строк,
   связность BFS от спавна и лестниц, две стороны у каждой двери,
   количество сущностей (N=4, f=3, n=3, P=1).
3. Легенда ASCII: `#`/пробел — стены, `.` пол, `+` дверь, `H` люк,
   `1`/`2` лестницы (связи в `Game.STAIR_LINK`), `P` спавн игрока,
   `M`/`m` точки патруля монстра, `N` узел, `F` щиток, `f` предохранитель,
   `n` записка, `b` бутылка, `T` терминал, `x` динамик, `W` окно,
   `L` лампа, `l` мигающая лампа, `r` красный маячок.
4. 1 клетка = 2 м (`LevelBuilder.CELL`).

## 3. Сцены
- `scenes/main.tscn` — пустой Node3D «Main» + `main.gd`. Всё, включая
  игрока и монстра, строится кодом. Это осознанное решение: нечего
  рассинхронизировать между .tscn и скриптами.
- Player (CharacterBody3D): CollisionShape капсула; Camera3D на высоте
  1.68 м (1.12 присед); RayCast3D от камеры (2.3 м, mask=8,
  collide_with_areas=true); SpotLight3D фонаря (range 13, angle 27°,
  shadows on, bias 0.03, normal 1.2) — единственные динамические тени.
- Monster (CharacterBody3D): капсула, layer 4, тёмный материал без
  emission (слепой — его видно только силуэтом в свете игрока);
  AudioStreamPlayer3D шагов и presence-гул как ребёнок ноды.

## 4. Построение уровня (level_builder.gd)
1. `build(map)` читает ASCII: floor/ceiling — единые плиты на этаж;
   стены — слияние горизонтальных прогонов в MeshInstance3D + StaticBody3D
   (layer 1). Стены толщиной в целую клетку (2 м) — deliberate защита
   от light leaks.
2. `x` — стеновая ниша с динамиком (box + AudioStreamPlayer3D
   radio_loop −22 dB, пишется в `speaker_positions` для мимикрии main.gd).
3. `W` — окно: эмиссионное стекло #9EB8EB (1.15) как «лунный свет»
   + холодный OmniLight3D без теней + loop `wind.wav`. Это физически
   оправданный единственный источник холодного света в помещениях.
4. `L`/`l` — светильник: корпус + эмиссионная панель + OmniLight3D
   (BAKE_DYNAMIC — кандидат для LightmapGI). `l` добавляется в список
   мигающих (`flick`): Timer со случайным интервалом и рывком энергии.
5. `r` — красный маячок (alarm-only красный), Tween-пульс.
6. Двери: `door_gate.gd` по оси (определяется по проходимым соседям),
   группа «doors», звук door_metal; люк `H` открывается сигналом
   `Game.node_activated`.
7. Мебель: `_furnish_rooms` — seeded RNG на каждый room-rect, стили
   guardpost/hall/office/radio/server/oproom/shower/storage/canteen/lift/
   stairs/generator/boiler/gallery/tunnel/cage/archive/machine/corridor.
   Мелкий декор — без коллизий (`_decor_room`, декали Decal-нодами).

## 5. Навигация монстра
- NavigationServer не используется. `monster.gd` держит AStarGrid2D
  (DIAGONAL_MODE_NEVER, MANHATTAN), перестраивается на смене этажа.
- Путь: `astar.get_id_path` → `Array[Vector2i]` → мировые координаты через
  `Game.main.cell_to_world(floor_id, cell)` (main делегирует в builder).
- Слух: сигнал `Game.emit_noise(pos, floor_id, loudness)`. Радиусы:
  присед 2.5, шаг 8, бег 19, бутылка 26, дверь 12, узел 26–30.
  Между этажами слышно только при loudness ≥ 15 и с ослаблением ×0.4.
- Состояния: PATROL / INVESTIGATE / HUNT / LISTEN. Скорости 1.6 / 2.4 / 4.4.
  HUNT при d < 9; теряет игрока при приседе и тишине; catch при d < 1.5.

## 6. Свет и окружение
- `main.gd` собирает WorldEnvironment в коде: фон #030405, тонемап FILMIC,
  exposure 1.0 ФИКСИРОВАННЫЙ (CameraAttributes НЕ добавляется — это и
  отключает auto exposure), white 6.0. Fog включается на этаж в
  `_apply_floor_env` с плотностью 0.028 (Б1) / 0.012 (1) / 0.016 (2).
- Палитра строго из четырёх значений: 2700K аварийный тёплый, 4000K
  люминесцентный, 6500K лунный/зимний, красный — только тревога и
  красная дверь Б1. Эмиссия экранов узлов — единственный акцент #5CC78D.
- Виньетка: canvas-шейдер на ColorRect в HUD (не постпроцесс сцены).
- Свет как проводник: окна, лампы над проёмами, красная дверь тоннеля,
  мигающая лампа как landmark. Полное затухание света в клетках без
  источников не допускается (правило ≥2 уровней освещённости в комнате).

## 7. Звук
- 24 WAV сгенерированы `tools/make_sounds.py` (22.05 кГц, 16 бит, моно).
- `sound_bank.gd` грузит их всюду, ставит LOOP_FORWARD для loop-списка
  (loop_end = data.size()/2), хелперы: `play_at` (one-shot с автоудалением),
  `make_loop` (позиционный loop), `make_2d` (UI/финал).
- Слои: глобальный room-дрон + позиционные капли/ветер/радио + шаги
  монстра + редкие one-shot (стинг, шёпот) + таймер мимикрии в main.gd
  (раз в 45–85 с играет `mimic` из случайного динамика этажа монстра
  дальше 10 м от игрока).

## 8. Геймплейные связи
- Прогресс: 3 предохранителя (f) → щиток (F) → питание → 4 узла (N,
  radio_node.gd, шум 26–30 м при активации) → люк `H` → техтоннель Б1 →
  терминал (T) → выбор финала (1/2) → ENDINGS из station_data.gd.
- Смерть: caught() → статика + fade 0.55 с → пересбор текущего этажа;
  прогресс узлов/предохранителей сохраняется; `Game.deaths++`.
- Смена этажа: `Game.main.change_floor(fid)` — фейд, LevelBuilder.build,
  игрок на клетку `1`/`2`, монстр переносится на самую дальнюю клетку
  патруля от игрока («честный» респавн).

## 9. Проверка
Открыть проект в Godot 4.3 → F5. Чеклисты: docs/QA.md (свет/наполнение/
производительность/лицензии) и docs/LIGHTING.md (параметры).
